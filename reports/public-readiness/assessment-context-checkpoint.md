The additive `App.assessAllTeamsWithContext(rosters, players, playerStats, league, leagueUsers, tradedPicks, context)` capability requires `{ leagueId, season, playerScores, isCurrent }`. It supplies owned values throughout the existing calculation, requires matching league/season and usable score data, checks the caller at entry/return, and never adopts the active bridge's draft list. A separate capability name prevents an older shared pin from silently ignoring an extra argument. The old generic API remains compatible and also accepts the optional seventh context argument internally.

Healthy explicit output matches the old selected-league calculation exactly under standard, superflex, custom-IDP and missing-season-point fixtures. Injury handling, inactive/retired value handling, pick ownership evidence and all health/rank weights remain unchanged. The adapter writes no global `S`, `App.LI`, `DhqBrain`, local storage, cloud pin or owner record. It does not silently enable the existing one-brain overlay: canonical `assessAllTeams` has never applied that overlay, and the `FromGlobal` wrapper currently gates it on the V2 flag. Correcting that cross-module behavior is a separate owner-contract question to establish from current source decisions, not an incidental context change.
